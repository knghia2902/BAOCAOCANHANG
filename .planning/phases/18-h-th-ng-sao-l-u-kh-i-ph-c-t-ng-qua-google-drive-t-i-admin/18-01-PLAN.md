<task id="18-01-02">
<title>Xây dựng BackupService.ts với tính năng đóng gói ZIP toàn hệ thống (DB + Storage) và Khôi phục (Restore)</title>
<action>
Tạo file `src/services/storage/BackupService.ts` với đầy đủ các interface và phương thức sau:
1. **Định nghĩa kiểu dữ liệu:**
   - `BackupConfig`:
     - `enabled: boolean` (bật/tắt tự động sao lưu theo giờ)
     - `scheduleTime: string` (định dạng `"HH:mm"`, mặc định `"23:00"`)
     - `maxBackups: number` (số bản sao lưu tối đa giữ lại trên Drive, mặc định `7`)
     - `includeStorage: boolean` (sao lưu kèm hình ảnh & tài liệu, mặc định `true`)
     - `gasWebhookUrl: string` (URL Web App của Google Apps Script)
     - `driveFolderId: string` (ID thư mục Google Drive hoặc link thư mục — tự động trích xuất Folder ID nếu người dùng dán nguyên link URL thư mục Google Drive)
     - `lastBackupAt: string | null`
     - `lastBackupStatus: string | null`
     - `lastBackupFileName: string | null`
   - `DriveBackupItem`: `{ id: string; name: string; createdTime: string; sizeBytes: number; downloadUrl?: string; webViewLink?: string }`
   - `BackupManifest`: `{ version: string; timestamp: string; createdBy: string; tables: Record<string, { records: number; sizeBytes: number }>; storageFiles: Array<{ path: string; contentType: string; sizeBytes: number }>; totalRecords: number; totalSizeBytes: number }`
   - `BackupProgressCallback`: `(step: string, percent: number) => void`

2. **Danh sách toàn bộ các bảng cần sao lưu (`BACKUP_TABLES`):**
   - `content` (PK: `id`)
   - `projects` (PK: `id`)
   - `tools` (PK: `id`)
   - `messages` (PK: `id`)
   - `users` (PK: `username`)
   - `activity_logs` (PK: `id`)
   - `vehicle_profiles` (PK: `id`)
   - `weighbridge_vehicles` (PK: `id`)
   - `weighbridge_vessels` (PK: `id`)
   - `weighbridge_barges` (PK: `id`)
   - `weighbridge_trucks` (PK: `id`)
   - `weighbridge_tracking` (PK: `id`)
   - `weighbridge_allocation_tracking` (PK: `id`)
   - `allocator_history_trips` (PK: `id`)
   - `weighbridge_warehouse_tickets` (PK: `id`)
   - `weighbridge_container_tickets` (PK: `id`)

3. **Hàm đọc toàn bộ dữ liệu bảng phân trang (`fetchAllTableRows(tableName)`):**
   - Sử dụng vòng lặp `.range(from, from + pageSize - 1)` với `pageSize = 1000` để lấy hết 100% bản ghi kể cả các bảng lớn như `weighbridge_trucks` hoặc `allocator_history_trips` (>15,000 dòng). Nếu bảng nào chưa tồn tại trên Supabase thì bỏ qua an toàn (trả về mảng rỗng `[]`).

4. **Hàm quét đệ quy và tải toàn bộ hình ảnh/tài liệu trên Supabase Storage (`fetchAllStorageFiles`):**
   - Duyệt đệ quy bucket `portfolio-assets` từ thư mục gốc `''` và các thư mục con (`general`, `hero`, `projects`, `barges`, `vessels`, `minutes`...).
   - Tải từng file qua `supabase.storage.from('portfolio-assets').download(path)` và đưa vào thư mục `storage/{path}` trong gói `JSZip`.

5. **Hàm tạo gói nén `.zip` (`createBackupZip(includeStorage, onProgress)`):**
   - Thu thập toàn bộ bảng vào `database/{tableName}.json`.
   - Thu thập toàn bộ file Storage vào `storage/{filePath}`.
   - Tạo `manifest.json` ở thư mục gốc của file `.zip`.
   - Nén bằng `JSZip` với `compression: 'DEFLATE'`, `compressionOptions: { level: 6 }`, trả về `{ blob, fileName, manifest }`.

6. **Hàm khôi phục từ gói `.zip` (`restoreFromZipBlob(fileOrBlob, onProgress)`):**
   - Giải nén bằng `JSZip.loadAsync(fileOrBlob)`, đọc và kiểm tra `manifest.json`.
   - Khôi phục dữ liệu các bảng theo đúng thứ tự phụ thuộc khóa ngoại (`content`, `users`, `projects`, `tools`, `messages`, `vehicle_profiles`, `weighbridge_vehicles`, `weighbridge_vessels` -> `weighbridge_barges` -> `weighbridge_trucks`, `weighbridge_tracking`, `weighbridge_allocation_tracking`, `allocator_history_trips`, `weighbridge_warehouse_tickets`, `weighbridge_container_tickets`, `activity_logs`) bằng `.upsert(batch, { onConflict: pk })` chia theo lô 500 bản ghi/lần.
   - Khôi phục toàn bộ file trong `storage/*` lên lại bucket `portfolio-assets` với `upsert: true`.
   - Trả về kết quả tổng số bản ghi và số file hình ảnh/tài liệu đã khôi phục.
</action>

<task id="18-01-03">
<title>Tích hợp giao thức Google Apps Script Bridge, Bộ lập lịch tự động theo giờ và Xoay vòng bản lưu</title>
<action>
Trong `src/services/storage/BackupService.ts`, bổ sung:
1. **Quản lý cấu hình `BackupConfig`:**
   - `loadConfig()`: Đọc từ `content.settings.backupConfig` trên Supabase (kèm fallback `localStorage`).
   - `saveConfig(config: BackupConfig)`: Lưu vào `content.settings.backupConfig` trên Supabase và cập nhật `localStorage`.
   - `extractFolderId(input: string)`: Tự động tách Folder ID nếu người dùng dán nguyên đường dẫn `https://drive.google.com/drive/folders/1a2b3c...`.

2. **Giao tiếp Google Drive qua Google Apps Script Web App (`gasWebhookUrl`):**
   - Dùng `fetch(config.gasWebhookUrl, { method: 'POST', headers: { 'Content-Type': 'text/plain;charset=utf-8' }, body: JSON.stringify(payload) })` (sử dụng `text/plain` để tránh lỗi CORS preflight với Google Apps Script Web App!).
   - `uploadToGoogleDrive(blob, fileName, config, onProgress)`:
     - Chuyển `blob` sang `base64`, gửi lệnh `{ action: 'upload', folderId, fileName, mimeType: 'application/zip', base64Data, maxBackups: config.maxBackups }` lên GAS Web App.
     - GAS sẽ tạo file `.zip` trên thư mục Google Drive đích, sau đó kiểm tra toàn bộ các file `backup_*.zip` trong thư mục: nếu số lượng vượt quá `maxBackups`, tự động chuyển các bản cũ nhất vào thùng rác (`setTrashed(true)`).
     - Cập nhật `lastBackupAt`, `lastBackupStatus`, `lastBackupFileName` vào `BackupConfig`.
   - `listDriveBackups(config)`: Gửi `{ action: 'list', folderId }` để lấy danh sách các file backup trên Google Drive (sắp xếp mới nhất lên đầu).
   - `restoreFromGoogleDrive(fileId, config, onProgress)`: Gửi `{ action: 'download', fileId }` để lấy `base64Data` của file `.zip` từ Google Drive, chuyển thành `Blob` và gọi `restoreFromZipBlob`.
   - `deleteDriveBackup(fileId, config)`: Gửi `{ action: 'delete', fileId }` để xóa 1 bản sao lưu trên Drive.

3. **Bộ lập lịch tự động sao lưu theo giờ (`startAutoBackupScheduler`):**
   - Kiểm tra định kỳ mỗi 60 giây (và kiểm tra ngay sau khi khởi động ứng dụng 10 giây):
   - Nếu `config.enabled === true` và có `gasWebhookUrl`:
     - So sánh giờ hiện tại (`HH:mm`) với `config.scheduleTime`.
     - Nếu thời gian hiện tại $\ge$ `scheduleTime` trong ngày hôm nay VÀ `lastBackupAt` chưa phải là ngày hôm nay (sau khung giờ `scheduleTime`), đồng thời không có tiến trình backup nào đang chạy (`isRunning`), thì tự động chạy `runBackupToDrive()` ngầm và ghi `LogService.logAction('Sao lưu tự động', ...)`.

4. **Hàm sinh mã mẫu Google Apps Script (`getGoogleAppsScriptTemplate(supabaseUrl, supabaseKey)`):**
   - Trả về đoạn mã `Code.gs` hoàn chỉnh, sẵn sàng copy-paste vào `script.google.com`:
     - Có hàm `doPost(e)` xử lý đầy đủ 4 action: `upload` (kèm xoay vòng giữ lại đúng `maxBackups` bản mới nhất), `list`, `download`, `delete`.
     - Có hàm `autoScheduledBackupFromSupabase()` dành cho trường hợp Admin muốn bật thêm Time-driven Trigger trực tiếp trên máy chủ Google (chạy 24/7 kể cả khi tắt máy tính).
</action>
